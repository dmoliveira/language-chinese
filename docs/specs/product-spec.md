# Product Specification

## Vision

Build an open, accessible Chinese-learning repository and GitHub Pages site for English-speaking learners, especially people who want Chinese for technology, computer science, software, and AI/ML environments.

## Target users

### Primary users

- English-speaking beginners and lower-intermediate learners of Chinese.
- Learners preparing for technical collaboration, study, research, or work.
- Self-directed learners who prefer structured open materials.

### Secondary users

- General learners with no technical background.
- Educators and contributors who want reusable open materials.
- Developers who want to extend interactive learning tools.

## User needs

- Learn Chinese through a clear progression.
- Practice listening, reading, writing, and speaking.
- Access trustworthy explanations in English.
- Study with open or low-cost supporting resources.
- Prepare for real-world technical vocabulary without losing general-language foundations.
- Get feedback through quizzes, answer keys, rubrics, and lightweight AI-assisted tools.

## Value proposition

- Open educational structure with transparent sourcing.
- Beginner-friendly learning path with professional presentation.
- Technical Chinese integrated into a general-use curriculum.
- Static-first delivery that is easy to access, audit, and contribute to.

## Goals

1. Publish a public learning hub with clear module-based navigation.
2. Deliver structured content for listening, reading, writing, and speaking.
3. Provide flashcards, answer keys, references, and study plans.
4. Support browser-based interactivity through JavaScript on GitHub Pages.
5. Maintain accessibility and licensing standards suitable for a public project.

## Non-goals

- Replacing formal language schools.
- Claiming exam equivalence or official certification.
- Building a heavy backend product in the first release.
- Republishing copyrighted materials without clear reuse rights.

## Success indicators

- Clear beginner onboarding path exists.
- Each core skill has at least one starter module.
- Every published audio lesson has a transcript.
- Every exercise has an answer key or rubric.
- Technical vocabulary content exists as a visible optional track.
- Public documentation makes contribution and reuse rules clear.

## Constraints

- GitHub Pages hosting constraints.
- Mixed licensing landscape for language-learning resources.
- Need for mobile-friendly, low-friction access.
- Need to keep the first iteration small enough to publish.

## Core feature set

- Markdown-based lessons and references.
- Interactive browser quizzes.
- Flashcards and review sets.
- Speaking prompts and recording/evaluation guidance.
- Writing exercises with manual and rubric-based feedback.
- Curated references to free and paid supporting resources.
- Study plans by time horizon and goal.

## Product quality requirements

- Professional tone and structure.
- Plain English explanations.
- Consistent metadata and difficulty labeling.
- Clear attribution and licensing notices.
- WCAG-oriented accessibility baseline.
